# 理论基础

## 先识别反复查找的问题

暴力写法如果反复问“x出现过吗、出现几次、对应哪个下标”，就考虑把答案提前记录下来。哈希用额外空间减少查找，HashMap/HashSet常见操作在哈希分布良好时可视为期望O(1)，不能把所有情况都写成严格O(1)。

## 哈希函数与碰撞

哈希函数把键映射到桶的位置。不同键可能进入同一桶，这叫碰撞，仍需按键的相等关系区分；常见处理有拉链法、开放寻址。Java的HashMap/HashSet处理底层碰撞，刷本章题目主要关注存什么和何时查询。

数组也能承担直接寻址表：例如26个小写字母用c-'a'映射到0～25，不需要额外的哈希函数。value % tableSize只是非负数上的简化示意，不能作为适用于任意整数的Java哈希实现，负数余数可能仍是负数。

## 数组、Set、Map怎么选

| 需求 | 首选结构 | 本章例子 |
|---|---|---|
| 键范围小且固定 | 数组：下标就是键，格子保存数量或标记 | 242、383；349也可用数组 |
| 只关心出现、去重、重复状态 | HashSet：保存值的集合 | 349、202 |
| 查到值后还需要下标或次数 | HashMap：key关联value | 1保存下标；454保存两数和次数 |
| 同一数组返回不重复三／四元组 | 排序+双指针：利用单调性移动和去重 | 15、18 |

## Java常用API：合并记忆

| 结构 | 操作 | 返回值与含义 |
|---|---|---|
| Set | add(x) / contains(x) / remove(x) | add：新加入才true；contains：是否存在；remove：是否移除 |
| Set | size() / isEmpty() | 不同值的数量 / 是否为空 |
| Map | put(key,value) | 新增或覆盖同键值，返回旧value（首次为null） |
| Map | get(key) / containsKey(key) | 取value，缺失返回null / 是否含键 |
| Map | getOrDefault(key,0) | 缺失时给0，本章统计次数用它 |
| Map | remove(key) / size() | 删除并返回旧value / 键值对数量 |

Map统计次数固定写成 count.put(key, count.getOrDefault(key, 0) + 1)。containsKey查的是键；containsValue遍历值，通常O(n)，不适合替代补数查询。Integer等包装类型比较数值用equals或拆箱，避免用==比较两个包装对象。

# 核心思想：先定义表里记录的事实

1. 我要反复查询什么？把它设为key。
2. 查询命中后还要什么？只要存在性用Set；要次数、下标等用Map；小范围用数组。
3. 表里记录的是全部供给、之前的元素，还是已经走过的状态？这决定先存还是先查。
4. 题目数的是下标组合，还是只要不同数值组合？这决定累加次数还是结果去重。

> 242看差值归零；383看库存非负；349看存在并去重；202看状态是否重复；1查之前的补数下标；454累加互补和的次数；15和18排序后固定值，再用双指针。

## [242. 有效的字母异位词](https://leetcode.cn/problems/valid-anagram/)

> 这道题本质是：比较两串字符的频率，而不是比较字符的位置。

### 拿到题目的第一思路

拿到题目，先看“重新排列后是否相同”。位置可以变，字符种类和每种字符的数量不能变。逐个配对需要反复查找；排序能让相同字符对齐，但还要 O(n log n)。题目只有26个小写字母，直接开26个计数格。

### 方法选择与步骤

主解选数组计数：count[i]表示 s 中第 i 种字母的数量减去 t 中的数量。数组下标就是字符的编码差，例如 b - a = 1。Set只记有没有，会丢掉重复次数。

1. 长度不同直接返回 false，异位词必须保留全部字符。
2. 用 s 的字符加库存，再用 t 的字符减库存。
3. 检查26个格子；全部为0才说明每种字符数量都相同。

### 实例走过程

1. s="aab"，t="aba"；只列 a、b 两格。
2. 遍历 s：a → [1,0]，a → [2,0]，b → [2,1]。
3. 遍历 t：a → [1,1]，b → [1,0]，a → [0,0]；返回 true。
4. 反例 s="aab"、t="abb"：最后是 [1,-1]，返回 false。

### Java：主解

```java
class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) {
            return false;
        }

        int[] count = new int[26];
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++;
        }
        for (int i = 0; i < t.length(); i++) {
            count[t.charAt(i) - 'a']--;
        }

        // 每个格子都归零，才是每种字母数量相同。
        for (int value : count) {
            if (value != 0) {
                return false;
            }
        }
        return true;
    }
}
```

### 易错点与复杂度

- 不能只比较不同字符的集合：aab 和 abb 的集合一样，次数不同。
- c - 'a' 依赖小写英文字母的题设；换成一般字符时要重新选择键和容量。

时间 O(n+m+26)，辅助空间 O(26)=O(1)。代码用 charAt 遍历，避免 toCharArray 额外复制整个字符串。

### 扩展解法：排序后逐位比较

学习扩展：把同一种字符排在相邻位置，再逐位比较。比数组计数慢，但不依赖26个计数格；本实现比较Java char，不能直接当成任意Unicode字素的处理方案。

用同一输入对照：同样输入aab、aba，排序后都变成aab，每一位都相等。

```java
import java.util.*;

class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) {
            return false;
        }
        char[] first = s.toCharArray();
        char[] second = t.toCharArray();
        Arrays.sort(first);
        Arrays.sort(second);
        return Arrays.equals(first, second);
    }
}
```

时间O(n log n+m log m)，char数组占O(n+m)辅助空间。

## [383. 赎金信](https://leetcode.cn/problems/ransom-note/)

> 这道题本质是：magazine提供字符库存，ransomNote逐个消耗，任何库存不足就失败。

### 拿到题目的第一思路

先别急着比较两串是否相等。magazine允许有剩余，只要它能提供ransomNote需要的每一个字符即可。逐个查找再删除字符需要反复扫描；只有26个小写字母，直接记每种字母的库存。

### 方法选择与步骤

沿用242的count命名和字符映射。区别在检查条件：242要求两边完全相等；383只要求提供方足够，结束时count可以为正。

1. 若需求长度大于供给长度，直接返回 false。
2. 遍历 magazine，增加对应字母的库存。
3. 遍历 ransomNote，每次减1；某格变成负数就失败。全部消耗完成则成功。

### 实例走过程

1. ransomNote="aa"，magazine="aab"；供给后 a=2、b=1。
2. 消耗第一个a：a=1；消耗第二个a：a=0。
3. 需求已全部满足，虽然 b=1 仍有剩余，也要返回 true。
4. 若 magazine="ab"：第一次消耗a后为0，第二次变成-1，立刻返回 false。

### Java：主解

```java
class Solution {
    public boolean canConstruct(String ransomNote, String magazine) {
        if (ransomNote.length() > magazine.length()) {
            return false;
        }

        int[] count = new int[26];
        for (int i = 0; i < magazine.length(); i++) {
            count[magazine.charAt(i) - 'a']++;
        }
        for (int i = 0; i < ransomNote.length(); i++) {
            int index = ransomNote.charAt(i) - 'a';
            count[index]--;
            // 可以有剩余，但不能出现欠缺。
            if (count[index] < 0) {
                return false;
            }
        }
        return true;
    }
}
```

- 不能要求所有格子最后都归零，那会误判供给有剩余的情况。
- 需求每个字符只能消耗一次库存；Set无法区分一个a和两个a。

## [349. 两个数组的交集](https://leetcode.cn/problems/intersection-of-two-arrays/)

> 这道题本质是：查询另一个数组中有没有这个数，并让答案中的数值只出现一次。

### 拿到题目的第一思路

最直接的办法是对 nums2 的每个数，扫描 nums1 查找，时间 O(nm)。重复查询的都是“nums1中有没有x”，所以先记录 nums1 的数值。答案要求去重，但不要求出现次数和顺序，两个 Set 正好分别完成查找和结果去重。

### 方法选择与步骤

主解用 HashSet；题设的数值范围0～1000也允许数组标记，后面给出这一版。先根据要保存的信息选择结构，再比较范围带来的优化空间。

1. 将 nums1 的元素加入 seen，忽略其内部重复值。
2. 遍历 nums2；seen 中存在的数加入 result，result 自动去重。
3. 把 result 逐个放入 int[] 返回，顺序任意。

### 实例走过程

1. nums1=[1,2,2,1]，nums2=[2,2]。
2. 建表后 seen={1,2}。第一次查询2命中，result={2}。
3. 第二次查询2仍命中，再加入2不会增加集合大小。
4. 把集合转为数组，得到 [2]；不能返回 [2,2]。

### Java：主解

```java
import java.util.*;

class Solution {
    public int[] intersection(int[] nums1, int[] nums2) {
        Set<Integer> seen = new HashSet<>();
        Set<Integer> result = new HashSet<>();
        for (int value : nums1) {
            seen.add(value);
        }
        for (int value : nums2) {
            // seen 负责查找，result 负责答案去重。
            if (seen.contains(value)) {
                result.add(value);
            }
        }

        int[] answer = new int[result.size()];
        int index = 0;
        for (int value : result) {
            answer[index++] = value;
        }
        return answer;
    }
}
```

### 易错点与复杂度

- 题目要求数值去重；如果要求保留重复次数，那是另一类计数题。
- HashSet遍历顺序不固定，核对答案时按集合语义比较。

主解期望时间 O(n+m)，辅助空间 O(n+m) 的宽松上界；实际取决于两个集合中的不同值数。返回数组另占 O(k)，k为交集大小。

### 扩展解法：固定范围数组标记

对应原文Java数组思路：题设0≤nums[i]≤1000，直接用数值当下标。inFirst保存nums1中是否存在，inResult保存交集是否已记录。与Set的差别在键如何存储，查找和答案去重仍是两件事。

用同一输入对照：仍用[1,2,2,1]和[2,2]：inFirst[2]=true；两个2都把inResult[2]设为true，最后扫描只输出一次2。

```java
class Solution {
    public int[] intersection(int[] nums1, int[] nums2) {
        boolean[] inFirst = new boolean[1001];
        boolean[] inResult = new boolean[1001];
        for (int value : nums1) {
            inFirst[value] = true;
        }
        int size = 0;
        for (int value : nums2) {
            if (inFirst[value] && !inResult[value]) {
                inResult[value] = true;
                size++;
            }
        }
        int[] answer = new int[size];
        int index = 0;
        for (int value = 0; value < inResult.length; value++) {
            if (inResult[value]) {
                answer[index++] = value;
            }
        }
        return answer;
    }
}
```

时间O(n+m+U)，辅助空间O(U)，U=1001；题设下为常量。范围扩大或有负数时不能原样套用。

## [202. 快乐数](https://leetcode.cn/problems/happy-number/)

> 这道题本质是：反复生成下一个状态，判断最终到1，还是进入重复状态的环。

### 拿到题目的第一思路

按题意不断计算各位数字的平方和即可，难点是“什么时候停”。如果没到1却再次遇到同一个数，之后的变化也会完全重复，不必再算。把计算过的整个数存进 Set，就能发现环。

### 方法选择与步骤

主解用 Set 保留历史状态，便于理解。这里记录的是每一轮的数，不是各个数位；getNext只负责把一个数变成下一个数。扩展用快慢指针检测同一条状态链，省掉集合。

1. 当前 n 为1，成功结束。
2. 若 seen 已包含 n，说明进入环，返回 false；否则记录 n。
3. 调用 getNext(n)：不断用 %10 取末位、/10 去末位，将平方累加，然后回到第一步。

### 实例走过程

1. n=19：先记录19；个位9贡献81，十位1贡献1，所以下一个数为82。
2. 19 → 82 → 68 → 100 → 1；每轮先检查当前状态，遇到1返回 true。
3. 非快乐数示例：2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4。
4. 第二次遇到4时，seen中已经有4；后续还会走相同路线，所以返回 false。

### Java：主解

```java
import java.util.*;

class Solution {
    public boolean isHappy(int n) {
        Set<Integer> seen = new HashSet<>();
        while (n != 1) {
            if (seen.contains(n)) {
                return false;
            }
            seen.add(n); // 保存本轮整个数，下一轮检查是否重复。
            n = getNext(n);
        }
        return true;
    }

    private int getNext(int n) {
        int sum = 0;
        while (n > 0) {
            int digit = n % 10;
            sum += digit * digit;
            n /= 10;
        }
        return sum;
    }
}
```

展老师小课堂：[打开本题独立调试器](https://xiaoshupeiqi.github.io/leetcode-java/problems/0202-happy-number/)

### 易错点与复杂度

- seen记录的是轮次状态，例如19、82、68；记录9、1等单个数位不能判断整条链是否重复。
- 先把 sum 设为0；取完一位后必须 n /= 10，否则取位循环不会结束。

设首个数有 d 位、共经过 k 个不同状态：直观上界为 O(kd) 时间、O(k)空间。十进制平方和会迅速把大数压缩到有限范围，按整数n的位数可写为 O(log n) 时间，Set空间常用 O(log n) 上界；本题32位正整数下，状态范围有固定上界。

### 扩展解法：快慢指针判环

对应原文Java快慢指针版本：把getNext看作“下一节点”。慢指针每轮一步，快指针两步；有限状态链有环时两者会相遇。到1后getNext(1)仍为1，所以相遇于1代表成功，其他位置代表非快乐数环。

用同一输入对照：n=19：慢/快依次为82/68、68/1、100/1、1/1；相遇值为1。n=2最终在非1环内相遇，返回false。

```java
class Solution {
    public boolean isHappy(int n) {
        int slow = n;
        int fast = n;
        // 初始相同也要先移动一次，不能一开始就判相遇。
        do {
            slow = getNext(slow);
            fast = getNext(getNext(fast));
        } while (slow != fast);
        return slow == 1;
    }

    private int getNext(int n) {
        int sum = 0;
        while (n > 0) {
            int digit = n % 10;
            sum += digit * digit;
            n /= 10;
        }
        return sum;
    }
}
```

时间仍由状态链和取位计算决定，常用O(log n)上界；辅助空间O(1)，代价是每轮调用getNext更多次。

## [1. 两数之和](https://leetcode.cn/problems/two-sum/)

> 这道题本质是：遍历当前数时，快速找到之前出现过的补数及其下标。

### 拿到题目的第一思路

先想枚举两个下标，时间 O(n²)。固定当前数x后，另一个数其实已经确定为 target-x，不必再枚举所有数。题目返回的是下标，所以只存数值的 Set 不够，要用 Map 将数值关联到下标。

### 方法选择与步骤

map 的 key 是数值，value 是它之前出现的一个下标。循环开始时，map只包含下标小于i的元素。这个范围约定让当前元素不会和自己配对。

1. 计算 need = target - nums[i]。
2. 先查 need；如果存在，返回 map.get(need) 和 i。
3. 查询失败后，才把 nums[i] → i 登记到 map。重复值覆盖旧下标也能保留一个可用位置。

### 实例走过程

1. nums=[2,7,11,15]，target=9；初始 map={}。
2. i=0，当前2，需要7；没找到，登记 {2:0}。
3. i=1，当前7，需要2；命中下标0，返回 [0,1]。
4. 再看 nums=[3,3]、target=6：第一个3先登记；第二个3查到第一个，返回 [0,1]。
5. 如果先把当前3存进去再查询，会错误地把同一个下标当成两个元素。

### Java：主解

```java
import java.util.*;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> map = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            // 此时 map 只含之前的元素，不会重复使用当前下标。
            if (map.containsKey(need)) {
                return new int[]{map.get(need), i};
            }
            map.put(nums[i], i);
        }
        return new int[0];
    }
}
```

### 易错点与复杂度

- 不要写 map.containsValue(need)：补数存在于key，value保存下标；containsValue还需要线性扫描。

## [454. 四数相加 II](https://leetcode.cn/problems/4sum-ii/)

> 这道题本质是：把四层枚举拆成两组两数和，用“和 → 出现次数”统计互补组合。

### 拿到题目的第一思路

题目从四个数组中各取一个元素，直接枚举是 O(n⁴)。把等式 a+b+c+d=0 改写成 a+b=-(c+d)，先统计前两个数组所有下标对的和，后两个数组就能直接查询。注意题目数的是下标四元组的个数，相同数值来自不同下标也要分别计数。

### 方法选择与步骤

count 的 key 是 nums1、nums2 的两数和，value 是得到这个和的下标对数量。Set只能告诉我们存在一个和，不能告诉我们它能配出几组答案。

1. 两层循环遍历 nums1、nums2，用 getOrDefault(sum,0)+1 累加每种两数和。
2. 两层循环遍历 nums3、nums4，计算 need=-(c+d)。
3. 把 count.getOrDefault(need,0) 加到 result，而不是只加1。

### 实例走过程

1. nums1=[1,2]，nums2=[-2,-1]，nums3=[-1,2]，nums4=[0,2]。
2. 前两组得到 -1、0、0、1，因此 count={-1:1,0:2,1:1}。
3. c=-1,d=0，需要1，命中1次，result=1。
4. c=-1,d=2，需要-1，再命中1次，result=2；其余两对未命中。
5. 返回2。反例四个数组都为[0,0]：前半有4对，后半有4对，共4×4=16，不能去重成1。

### Java：主解

```java
import java.util.*;

class Solution {
    public int fourSumCount(int[] nums1, int[] nums2, int[] nums3, int[] nums4) {
        Map<Integer, Integer> count = new HashMap<>();
        for (int a : nums1) {
            for (int b : nums2) {
                int sum = a + b;
                count.put(sum, count.getOrDefault(sum, 0) + 1);
            }
        }

        int result = 0;
        for (int c : nums3) {
            for (int d : nums4) {
                int need = -(c + d);
                // 一个补数可能对应多组下标对，要累加次数。
                result += count.getOrDefault(need, 0);
            }
        }
        return result;
    }
}
```

## [15. 三数之和](https://leetcode.cn/problems/3sum/)

> 这道题本质是：排序后固定一个数，让另外两个数从两端夹逼，同时跳过重复数值组合。

### 拿到题目的第一思路

枚举三个位置是 O(n³)。固定一个数后，还要找两个数；可以哈希查询，但本题返回不重复数值组合，去重细节较多。题目不要求原下标，先排序：和小了就增大左端，和大了就减小右端，一次扫描解决固定i后的两数配对。

### 方法选择与步骤

用排序+双指针作为主解。i、left、right严格递增排列为 i<left<right，保证三个下标不同；排序把相同值放在一起，才能按层去重。哈希不是不能做，而是这里双指针更便于统一移动、剪枝和去重。

1. 排序数组，i从0枚举到n-3。若nums[i]>0，之后三个数都会大于0，可结束。
2. i>0且nums[i]==nums[i-1]时跳过当前i，避免重复的第一个值。
3. 令left=i+1、right=n-1；和小于0则left++，大于0则right--。
4. 和为0先保存答案，再跳过左右两端重复值，最后两个指针各走一步。

### 实例走过程

1. nums=[-1,0,1,2,-1,-4]，排序得到 [-4,-1,-1,0,1,2]。
2. i=0固定-4：即使后两数取1、2，总和仍小于0；本轮没有答案。
3. i=1固定-1：left=2取-1，right=5取2，和为0，保存[-1,-1,2]。
4. 跳过同值后两端向内移动：left=3取0，right=4取1，再得[-1,0,1]。
5. i=2也取-1，与上一轮固定值相同，直接跳过。
6. 反例[-1,-1,2]说明两个-1可以同时入答案；不能因为nums[i]==nums[i+1]就跳过第一个-1。

### Java：主解

```java
import java.util.*;

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        Arrays.sort(nums);
        for (int i = 0; i < nums.length - 2; i++) {
            if (nums[i] > 0) {
                break;
            }
            // 同一层固定值只处理一次，仍允许一组中有相同数值。
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            int left = i + 1;
            int right = nums.length - 1;
            while (left < right) {
                long sum = (long) nums[i] + nums[left] + nums[right];
                if (sum < 0) {
                    left++;
                } else if (sum > 0) {
                    right--;
                } else {
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    // 先保存，再跨过相同的左右值。
                    while (left < right && nums[left] == nums[left + 1]) {
                        left++;
                    }
                    while (left < right && nums[right] == nums[right - 1]) {
                        right--;
                    }
                    left++;
                    right--;
                }
            }
        }
        return result;
    }
}
```

- 固定值去重比较“本轮与上一轮”；左右指针去重发生在保存答案之后。

时间 O(n²)，含排序O(n log n)。排除返回结果，Java原地基本类型排序通常计O(log n)栈空间；结果另占O(k)，k为返回的三元组数。

## [18. 四数之和](https://leetcode.cn/problems/4sum/)

> 这道题本质是：在三数之和外再固定一个数，两层固定值去重，内部仍用双指针找目标和。

### 拿到题目的第一思路

四层枚举是 O(n⁴)。沿用15题，把k、i两个位置固定后，剩下两数仍能从两端查找，时间降为 O(n³)。题目目标可以是负数，四个数的和也可能超出int；不要机械照搬三数之和的“固定值>0就结束”。

### 方法选择与步骤

k<i<left<right保证四个位置不同。k层去重与上一k比较，i层去重只在当前k内部比较。主解先保留最清楚的两层固定+双指针；范围剪枝在后面单独说明，先掌握正确骨架。

1. 排序；k遍历到n-4，跳过与上一个k相同的数。
2. i从k+1遍历到n-3；只有i>k+1时才比较nums[i]和nums[i-1]。
3. left=i+1、right=n-1；用long求和，小了左移，大了右移。
4. 相等时收集四元组，跳过左右重复值，再向内移动。

### 实例走过程

1. nums=[1,0,-1,0,-2,2]，target=0；排序为[-2,-1,0,0,1,2]。
2. k=0取-2，i=1取-1；left=2取0，right=5取2，和=-1，left右移。
3. left=3仍取0，和仍为-1；left=4取1，和=0，保存[-2,-1,1,2]。
4. 同一k下，i=2取0，left=3取0、right=5取2，保存[-2,0,0,2]。
5. i=3与本轮前一个i取值相同，跳过；之后k=1、i=2得到[-1,0,0,1]。
6. 负数反例：[-5,-4,-3,-2]、target=-14。虽然-5>-14，四数仍能相加成-14，不能按“nums[k]>target”剪枝。

### Java：主解

```java
import java.util.*;

class Solution {
    public List<List<Integer>> fourSum(int[] nums, int target) {
        List<List<Integer>> result = new ArrayList<>();
        Arrays.sort(nums);
        for (int k = 0; k < nums.length - 3; k++) {
            if (k > 0 && nums[k] == nums[k - 1]) {
                continue;
            }
            for (int i = k + 1; i < nums.length - 2; i++) {
                // 只跳过当前 k 下面重复的第二个固定值。
                if (i > k + 1 && nums[i] == nums[i - 1]) {
                    continue;
                }
                int left = i + 1;
                int right = nums.length - 1;
                while (left < right) {
                    long sum = (long) nums[k] + nums[i] + nums[left] + nums[right];
                    if (sum < target) {
                        left++;
                    } else if (sum > target) {
                        right--;
                    } else {
                        result.add(Arrays.asList(nums[k], nums[i], nums[left], nums[right]));
                        while (left < right && nums[left] == nums[left + 1]) {
                            left++;
                        }
                        while (left < right && nums[right] == nums[right - 1]) {
                            right--;
                        }
                        left++;
                        right--;
                    }
                }
            }
        }
        return result;
    }
}
```

### 易错点与复杂度

- i的去重边界是i>k+1，不能写i>0，否则可能误删当前k下的第一个i。
- 必须先(long)nums[k]再加其余数；等int加完再强转已经来不及。四个10⁹会溢出int。
- 主解修改输入顺序；若复制后排序，另需O(n)空间。

时间 O(n³)，含排序。排除返回结果，Java排序通常计O(log n)栈空间；k个返回四元组另占O(k)。

### 理解主解后再加范围剪枝

学习扩展：固定k后，最小可行和为(long)nums[k]+nums[k+1]+nums[k+2]+nums[k+3]；它若大于target，后续k只会更大，可break。最大可行和为(long)nums[k]+nums[n-1]+nums[n-2]+nums[n-3]；它若仍小于target，只说明当前k不够，可continue。固定k、i后也可按相同方式取剩余两数的最小和与最大和。

例如[-5,-4,-3,-2]、target=-14，最小和恰等于-14，必须保留。所有边界求和同样要在第一次加法前转long。剪枝不改变最坏O(n³)，先能复写主解再加，避免把break和continue用反。
