## 1. 链表理论基础

### 节点、引用与三种链表

单链表节点保存val和next引用；head保存入口节点的引用，空链表head==null。Java节点对象不要求连续存放，不能像数组一样通过head[i]随机访问。

```java
class ListNode {
    int val;
    ListNode next;

    ListNode() {}

    ListNode(int val) {
        this.val = val;
    }

    ListNode(int val, ListNode next) {
        this.val = val;
        this.next = next;
    }
}
```

这是节点定义示意，不是某一道题的提交代码；160、141、142的平台节点模板只展示单参数构造函数，本章这几题的解法不调用其他构造函数。

| 结构 | 保存什么 | 能做什么 |
| --- | --- | --- |
| 单链表 | val、next | 只能沿next向后访问 |
| 双链表 | val、prev、next | 可向前、向后访问；增删要维护两边 |
| 循环链表 | 尾部连接到前面节点 | 沿next可能永不为null；检测要考虑环 |

### 和数组相比，先分清查找与改线

| 操作 | 数组 | 单链表 |
| --- | --- | --- |
| 访问下标i | O(1) | 从头走O(i+1) |
| 已知前驱后插入/删除 | 保序通常需搬移后缀O(n) | 改常数条next，O(1) |
| 按下标插入/删除 | 保序最坏O(n) | 找前驱最坏O(n)，改线O(1) |
| 长度与空间 | Java数组长度固定；扩容需新数组 | 节点数可变化，每节点额外保存引用 |

### 两个动作形成同一套模板

```text
插入：pre → next 变为 pre → newNode → next
newNode.next = pre.next;
pre.next = newNode;

删除：pre → target → next 变为 pre → next
pre.next = pre.next.next;

移动观察位置：cur = cur.next;    // 不会修改节点之间的连线
```

Java的java.util.LinkedList是双链表集合；它的get(index)仍需遍历。题目707要求自己实现，不能用库代替。删除后若某节点不再被任何可达引用持有，才可能由垃圾回收器回收；不需要也不能照搬C++的delete。

### 看到什么特征，先想到什么

| 特征 | 优先方法 | 先固定的位置 |
| --- | --- | --- |
| 头节点也可能被删或交换 | dummy | 真实头始终由dummy.next取得 |
| 整条next方向翻转 | prev、cur、next | 已反转前缀/待处理后缀 |
| 局部相邻节点交换 | 前驱＋first/second | 一对交换后谁是下一对前驱 |
| 倒数第n个 | 固定间距双指针 | fast停null还是尾节点 |
| 两链表共享后缀 | 长度对齐/换头 | 比较对象引用 |
| 有环/入口 | 快慢指针 | 先找相遇点，再找入口 |

## 2. 虚拟头结点与删除

### [203. 移除链表元素](https://leetcode.cn/problems/remove-linked-list-elements/)

[交互式调试器 · 203. 移除链表元素](https://xiaoshupeiqi.github.io/leetcode-java/problems/0203-remove-linked-list-elements/)

#### 一句话总结

> 这道题本质是：让前驱跨过所有待删节点；删除后先检查新的后继。

#### 拿到题目怎么想

1. 读到“删除所有等于val的节点”，先想到从头扫描。单链表不能直接找到当前节点的前一个节点，删除要改前驱的next。
2. 如果头节点也要删，head需要单独更新。加dummy指向head后，头节点和中间节点都有前驱。
3. 让cur停在前驱，检查cur.next。命中就跨过；没命中才让cur前进。删除后不前进，因为新的cur.next还没检查。
4. cur.next为空时处理完毕，返回dummy.next，覆盖空链表和全部删除。

#### 关键变量与循环不变量

dummy只提供前驱，不属于答案。每轮开始时，dummy到cur之间的真实节点均已确认保留，cur.next是下一个待检查节点。

#### 实例走过程

```text
head=[6,6,1,6], val=6
dummy → 6a → 6b → 1 → 6c → null，cur=dummy
删6a：dummy → 6b → 1 → 6c，cur不动
删6b：dummy → 1 → 6c，cur不动
保留1：cur从dummy移到1
删6c：1.next=null，退出，返回[1]
```

#### Java主解

```java
class Solution {
    public ListNode removeElements(ListNode head, int val) {
        ListNode dummy = new ListNode(0, head);
        ListNode cur = dummy;
        while (cur.next != null) {
            if (cur.next.val == val) {
                cur.next = cur.next.next; // 删除后，继续检查新的后继
            } else {
                cur = cur.next; // 当前后继保留，才向前走
            }
        }
        return dummy.next;
    }
}
```

#### 易错点与复杂度

连续命中时不能无条件移动cur；返回dummy.next而不是head或dummy。删除只是改变可达关系，Java不手动释放节点。

时间O(n)，额外空间O(1)。

#### 扩展解法与方法对比

##### 递归：先处理后缀，再决定当前节点

对应代码随想录Java递归版。用于理解“返回的新头必须接回”；长链表优先主解。

1. 函数含义：removeElements(head,val)返回从head开始删除目标值后的新头。
2. 终止：head==null返回null。
3. 本层：先递归处理head.next并接回；当前值等于val就返回后继，否则返回head。

同一输入递归到null；回程依次：6c返回null，1接null并返回1，6b返回1，6a返回1。

```java
class Solution {
    public ListNode removeElements(ListNode head, int val) {
        if (head == null) {
            return null;
        }
        head.next = removeElements(head.next, val); // 接回处理后的后缀
        if (head.val == val) {
            return head.next;
        }
        return head;
    }
}
```

时间O(n)，递归栈O(n)；Java不保证尾调用优化。

| --- | --- | --- |
| 主解（调试器对应） | dummy只提供前驱，不属于答案。每轮开始时，dummy到cur之间的真实节点均已确认保留，cur.next是下一个待检查节点。 | 时间O(n)，额外空间O(1)。 |
| 递归：先处理后缀，再决定当前节点 | 对应代码随想录Java递归版。用于理解“返回的新头必须接回”；长链表优先主解。 | 时间O(n)，递归栈O(n)；Java不保证尾调用优化。 |

### 原文重点标记

> **给原链表前面人为加一个 ****dummy****，让“****删除头结点”和“删除普通节点”统一成同一种操作****。**

## 3. 链表基本操作

### [707. 设计链表](https://leetcode.cn/problems/design-linked-list/)

[交互式调试器 · 707. 设计链表](https://xiaoshupeiqi.github.io/leetcode-java/problems/0707-design-linked-list/)

#### 一句话总结

> 这道题本质是：用dummy统一前驱，用size区分访问范围与插入范围。

#### 拿到题目怎么想

1. 先把接口还原为两个动作：沿next找到位置，修改局部连线。题目要求自己实现，不能直接调用LinkedList。
2. get和delete的合法下标为[0,size)；插入允许index==size，即[0,size]。边界先判断，再找节点。
3. 统一从dummy出发走index步，就站在下标index的前驱。插入先让新节点接后面，再让前驱接新节点；删除让前驱跨过目标。
4. 头插复用addAtIndex(0,val)，尾插复用addAtIndex(size,val)。每次实际增删后才修改size。

#### 关键变量与循环不变量

size始终等于真实节点数，不含dummy。get从dummy.next走index步到目标；增删从dummy走index步到前驱。

#### 实例走过程

```text
new MyLinkedList()      []          size=0
addAtHead(1)            [1]         size=1
addAtTail(3)            [1,3]       size=2
addAtIndex(1,2)         [1,2,3]     size=3
  pre=1，新2.next=3，再令1.next=新2
get(1)                 返回2
deleteAtIndex(1)        [1,3]       size=2
get(1)                 返回3
```

#### Java主解

```java
class MyLinkedList {
    private static class ListNode {
        int val;
        ListNode next;
        ListNode(int val) {
            this.val = val;
        }
    }

    private final ListNode dummy;
    private int size;

    public MyLinkedList() {
        dummy = new ListNode(0);
        size = 0;
    }

    public int get(int index) {
        if (index < 0 || index >= size) {
            return -1;
        }
        ListNode cur = dummy.next;
        for (int i = 0; i < index; i++) {
            cur = cur.next;
        }
        return cur.val;
    }

    public void addAtHead(int val) {
        addAtIndex(0, val);
    }

    public void addAtTail(int val) {
        addAtIndex(size, val);
    }

    public void addAtIndex(int index, int val) {
        if (index < 0 || index > size) {
            return;
        }
        ListNode pre = dummy;
        for (int i = 0; i < index; i++) {
            pre = pre.next;
        }
        ListNode newNode = new ListNode(val);
        newNode.next = pre.next; // 先保住后缀
        pre.next = newNode;
        size++;
    }

    public void deleteAtIndex(int index) {
        if (index < 0 || index >= size) {
            return;
        }
        ListNode pre = dummy;
        for (int i = 0; i < index; i++) {
            pre = pre.next;
        }
        pre.next = pre.next.next;
        size--;
    }
}
```

#### 易错点与复杂度

访问和删除不允许index==size，插入允许。当前力扣约束index>=0；此处保留原文“负下标无效”的防御行为。旧版题意若要求负插入下标视为0，应在判上界后先执行index=Math.max(0,index)。

get、指定位置增删时间O(index+1)，最坏O(n)；头插O(1)，本版尾插O(n)。整条链表存储O(n)，单次操作额外空间O(1)。

#### 扩展解法与方法对比

##### 双链表：头尾哨兵与就近查找

对应代码随想录双链表思路，统一为head/tail两个哨兵。主要收益是尾插O(1)和查找可从近端开始。

1. 空表为head↔tail；两个哨兵不计入size。nodeAt(index)从距离更近的一端找真实节点。
2. 插入先定位后继next；index==size时后继是tail。令prev=next.prev，连接prev↔新节点↔next。
3. 删除同时接好两侧：prev.next=next，next.prev=prev。多维护一个prev引用，换来向前访问能力。

同一操作序列得到[1,2,3]；删除2时同时令1.next=3、3.prev=1；两次get仍返回2、3。

```java
class MyLinkedList {
    private static class Node {
        int val;
        Node prev;
        Node next;
        Node(int val) {
            this.val = val;
        }
    }

    private final Node head;
    private final Node tail;
    private int size;

    public MyLinkedList() {
        head = new Node(0);
        tail = new Node(0);
        head.next = tail;
        tail.prev = head;
    }

    private Node nodeAt(int index) {
        if (index < size / 2) {
            Node cur = head.next;
            for (int i = 0; i < index; i++) {
                cur = cur.next;
            }
            return cur;
        }
        Node cur = tail.prev;
        for (int i = size - 1; i > index; i--) {
            cur = cur.prev;
        }
        return cur;
    }

    public int get(int index) {
        if (index < 0 || index >= size) {
            return -1;
        }
        return nodeAt(index).val;
    }

    public void addAtHead(int val) {
        addAtIndex(0, val);
    }

    public void addAtTail(int val) {
        addAtIndex(size, val);
    }

    public void addAtIndex(int index, int val) {
        if (index < 0 || index > size) {
            return;
        }
        Node next = tail;
        if (index < size) {
            next = nodeAt(index);
        }
        Node prev = next.prev;
        Node node = new Node(val);
        node.prev = prev;
        node.next = next;
        prev.next = node;
        next.prev = node;
        size++;
    }

    public void deleteAtIndex(int index) {
        if (index < 0 || index >= size) {
            return;
        }
        Node node = nodeAt(index);
        Node prev = node.prev;
        Node next = node.next;
        prev.next = next;
        next.prev = prev;
        size--;
    }
}
```

头尾插O(1)，有效下标访问和删除O(min(index,size-1-index)+1)，中间插入最坏O(n)；总存储O(n)，每节点多一个prev引用。

### 原文重点标记

下面“先找前驱”的记忆用语适用于增删；get直接定位目标节点即可。

> **链表的增删改查，本质都是“先走到目标位置的****前驱****节点，再改连接关系”。**

**顺序不能反。**

## 4. 反转链表

### [206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)

[交互式调试器 · 206. 反转链表](https://xiaoshupeiqi.github.io/leetcode-java/problems/0206-reverse-linked-list/)

#### 一句话总结

> 这道题本质是：把尚未处理的头节点取下，接到已反转部分的前面。

#### 拿到题目怎么想

1. 先确认反转的是next方向，不是交换val。要让当前节点指向前一个节点，需要prev记住已反转部分的头。
2. cur.next一旦改成prev，原后继就不能再通过cur.next找到，所以改线前先用next保存它。
3. 每轮严格四步：存后继 → 改方向 → prev移到cur → cur移到next。最后两步移动的是局部引用，不会自动改节点。
4. cur到null时所有节点处理完，prev是新头。空链表也自然返回null。

#### 关键变量与循环不变量

prev指向已经反转的前缀，cur指向尚未处理的后缀；next只暂存cur原后继。

#### 实例走过程

```text
head=[1,2,3]
初始：prev=null，cur=1，未处理1→2→3
处理1：next=2，1.next=null，prev=1，cur=2
处理2：next=3，2.next=1，prev=2，cur=3
处理3：next=null，3.next=2，prev=3，cur=null
返回prev：3→2→1→null
```

#### Java主解

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;
        ListNode cur = head;
        while (cur != null) {
            ListNode next = cur.next; // 改线前保存原后继
            cur.next = prev;
            prev = cur;
            cur = next;
        }
        return prev;
    }
}
```

#### 易错点与复杂度

不能改线后再cur=cur.next，那会走回已反转部分。循环终止时cur是null，返回prev。

时间O(n)，额外空间O(1)。

#### 扩展解法与方法对比

##### 递归一：把四步迭代改写为递归

保留原文已有递归版，对应代码随想录双指针递归思路。改变控制方式，指针动作和主解一致。

1. 函数含义：reverse(prev,cur)接收已反转前缀和未处理后缀，返回最终新头。
2. 终止：cur==null返回prev。
3. 本层：保存next、反转cur.next；递归reverse(cur,next)相当于把主解最后两次移动作为新参数。

同一输入调用reverse(null,1) → reverse(1,2) → reverse(2,3) → reverse(3,null)，返回3并逐层上传。

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        return reverse(null, head);
    }

    private ListNode reverse(ListNode prev, ListNode cur) {
        if (cur == null) {
            return prev;
        }
        ListNode next = cur.next;
        cur.next = prev;
        return reverse(cur, next);
    }
}
```

时间O(n)，递归栈O(n)；Java不会因此自动压成O(1)栈。

##### 递归二：回程反转后继的箭头

对应代码随想录从后向前反转的递归思路。用于区别“递下去时改线”和“返回时改线”。

1. 函数含义：reverseList(head)把以head为头的链表反转，返回新头。
2. 终止：空链表或只剩一个节点，直接返回head。
3. 本层：先让后缀反转；原来的后继已成为后缀尾部，让它指回head，再把head.next置null断开旧方向。始终返回newHead。

同一输入先递到3；回到2：3.next=2，2.next=null；回到1：2.next=1，1.next=null；新头一直是3。

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        if (head == null || head.next == null) {
            return head;
        }
        ListNode newHead = reverseList(head.next);
        head.next.next = head; // 原后继现在是反转后缀的尾
        head.next = null; // 断开旧方向，避免两节点成环
        return newHead;
    }
}
```

时间O(n)，递归栈O(n)。

| 递归二：回程反转后继的箭头 | 对应代码随想录从后向前反转的递归思路。用于区别“递下去时改线”和“返回时改线”。 | 时间O(n)，递归栈O(n)。 |

### 原文重点标记

**精髓：****先保存 ****cur.next****，****再反转****；否则后面的链表会直接丢失。**

> **存后继 → 改方向 → prev 前进 → cur 前进**

## 5. 局部换链 / 两两交换

### [24. 两两交换链表中的节点【经典补充题】](https://leetcode.cn/problems/swap-nodes-in-pairs/)

[交互式调试器 · 24. 两两交换链表中的节点](https://xiaoshupeiqi.github.io/leetcode-java/problems/0024-swap-nodes-in-pairs/)

#### 一句话总结

> 这道题本质是：固定每一对的前驱，把pre→first→second→后缀接成pre→second→first→后缀。

#### 拿到题目怎么想

1. 题目要求交换节点，不能只交换val。第一对会改变头节点，先加dummy统一处理。
2. 让pre站在当前一对的前面，先保存first和second。只有剩余至少两个节点才交换。
3. 按固定顺序接线：pre.next=second；first.next=second.next先保住后缀；second.next=first。
4. 交换后first变成这一对的末尾，也是下一对的前驱，所以pre=first。奇数个节点时最后一个原样保留。

#### 关键变量与循环不变量

pre之前的节点已完成交换；pre.next和pre.next.next是本轮first、second。交换后pre移到原first。

#### 实例走过程

```text
head=[1,2,3,4,5]，pre=dummy
第一对first=1、second=2：dummy→2→1→3→4→5
pre=1；第二对first=3、second=4：dummy→2→1→4→3→5
pre=3；只剩5，不满足两节点条件，返回[2,1,4,3,5]
```

#### Java主解

```java
class Solution {
    public ListNode swapPairs(ListNode head) {
        ListNode dummy = new ListNode(0, head);
        ListNode pre = dummy;
        while (pre.next != null && pre.next.next != null) {
            ListNode first = pre.next;
            ListNode second = first.next;
            pre.next = second;
            first.next = second.next; // 在second改线前保住后缀
            second.next = first;
            pre = first; // 原first变为已交换部分的末尾
        }
        return dummy.next;
    }
}
```

#### 易错点与复杂度

first.next=second.next必须早于second.next=first，否则可能自环。pre每轮移到first，不是second。仅修改next，不修改val。

时间O(n)，额外空间O(1)。

#### 扩展解法与方法对比

##### 递归：一层处理一对

对应代码随想录Java递归版；每次递归缩小两个节点。

1. 函数含义：swapPairs(head)返回当前后缀两两交换后的新头。
2. 终止：head为空或只有一个节点，返回head。
3. 本层：保存second，递归处理second.next；把head接到已处理后缀，再令second指向head，返回second。

同一输入先处理[5]返回5；[3,4]接成4→3→5；[1,2]接成2→1→4→3→5。

```java
class Solution {
    public ListNode swapPairs(ListNode head) {
        if (head == null || head.next == null) {
            return head;
        }
        ListNode second = head.next;
        ListNode rest = swapPairs(second.next);
        head.next = rest;
        second.next = head;
        return second;
    }
}
```

时间O(n)，递归栈O(n)。

### 原文重点标记

原文的cur与本节主解的pre是同一角色：待交换这一对的前驱。

**精髓：****cur**** 永远站在当前两个待交换节点的前面；****交换完后移动到这一对的末尾****。**

## 6. 前后双指针

### [19. 删除链表的倒数第 N 个结点](https://leetcode.cn/problems/remove-nth-node-from-end-of-list/)

[交互式调试器 · 19. 删除链表的倒数第 N 个结点](https://xiaoshupeiqi.github.io/leetcode-java/problems/0019-remove-nth-node-from-end-of-list/)

#### 一句话总结

> 这道题本质是：让slow停在目标前驱；fast走到哪里，决定初始间距。

#### 拿到题目怎么想

1. 最直接可以先求长度L，再删正数第L-n+1个节点。但能否一趟找到？让两个指针保持固定间距。
2. 删除要找前驱，且n可能等于长度，先用dummy。fast、slow都从dummy出发。
3. 本版fast先走n+1步，两者相隔n+1条next边；之后同步走，直到fast==null，此时slow正好是目标前驱。
4. slow.next=slow.next.next完成删除，返回dummy.next。题目保证1<=n<=长度，不额外改变无效输入的含义。

#### 关键变量与循环不变量

fast领先slow恰好n+1条边（把尾节点到null也计作一条）。同步移动保持差值，fast到null时slow.next是倒数第n个节点。

#### 实例走过程

```text
head=[1,2,3,4,5], n=2
fast、slow均在dummy；fast先走3步到3，slow仍在dummy
同步：(fast,slow)=(4,1)→(5,2)→(null,3)
slow=3为前驱，删除slow.next即4，返回[1,2,3,5]
边界：head=[1], n=1；fast走2步到null，slow停dummy，删除唯一节点
```

#### Java主解

```java
class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        ListNode fast = dummy;
        ListNode slow = dummy;
        for (int i = 0; i <= n; i++) {
            fast = fast.next; // 先拉开n+1条边
        }
        while (fast != null) {
            fast = fast.next;
            slow = slow.next;
        }
        slow.next = slow.next.next;
        return dummy.next;
    }
}
```

#### 易错点与复杂度

n+1步配fast!=null；另一种n步必须配fast.next!=null，两套边界不能混搭。n==长度时slow应停dummy。

时间O(L)，额外空间O(1)，L为链表长度；一趟表示不先单独统计长度。

#### 同一目标，两种间距约定

| 起点相同：dummy | 领先步数 | 同步停止条件 | slow最终位置 |
| --- | --- | --- | --- |
| 本章主解 | n+1 | fast==null | 目标前驱 |
| 另一种正确写法 | n | fast.next==null | 目标前驱 |

两套都成立；换了领先步数就要一起换停止条件。主解的fast允许在最后一次移动后变null，之后不会再解引用它。

#### 扩展解法与方法对比

##### 两趟扫描：先求长度

学习扩展，用正向下标核对双指针的前驱位置。

1. 先求长度length，目标的零基下标是length-n。
2. 从dummy走length-n步到前驱，再跨过目标。
3. 本版两次遍历更容易按下标核对，但与主解时间量级相同。

同一输入length=5，length-n=3；dummy走3步到节点3，再跨过4。

```java
class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        int length = 0;
        for (ListNode cur = head; cur != null; cur = cur.next) {
            length++;
        }
        ListNode dummy = new ListNode(0, head);
        ListNode pre = dummy;
        for (int i = 0; i < length - n; i++) {
            pre = pre.next;
        }
        pre.next = pre.next.next;
        return dummy.next;
    }
}
```

时间O(L)，额外空间O(1)，扫描两趟。

| 写法 | 选择依据 | 代价 |
| --- | --- | --- |
| 主解（调试器对应） | fast领先slow恰好n+1条边（把尾节点到null也计作一条）。同步移动保持差值，fast到null时slow.next是倒数第n个节点。 | 时间O(L)，额外空间O(1)，L为链表长度；一趟表示不先单独统计长度。 |

**精髓：****真正需要找到的不是倒数第 N 个节点，而是它的前一个节点****。**

> **涉及删除头结点 → dummy。**

## 7. 链表相交

### [160. 相交链表](https://leetcode.cn/problems/intersection-of-two-linked-lists/)

[交互式调试器 · 160. 相交链表](https://xiaoshupeiqi.github.io/leetcode-java/problems/0160-intersection-of-two-linked-lists/)

#### 一句话总结

> 这道题本质是：先消除两条链表的长度差，再同步比较是否为同一个节点。

#### 拿到题目怎么想

1. 先确认“相交”是共享同一节点对象。相同val的两个节点不算相交；共享节点之后，next路径也完全相同。题目保证无环。
2. 同时从头走会错位。分别统计lenA、lenB，让更长的一条先走长度差，剩余到null的距离就相等。
3. 之后两个指针每轮各走一步，第一次引用相等就是交点；没有交点则最终同时为null。
4. 只移动局部引用，不改原链表。网站“面试题02.07”与这里训练的是同一相交模型，使用已核对的160方法签名。

#### 关键变量与循环不变量

长度对齐后curA、curB到null的剩余边数相同；循环比较curA!=curB，而不是比较val。

#### 实例走过程

```text
共享后缀C：8→4→5（这里的三个节点是真正共享的对象）
A：4→1→C，长度5；B：5→6→1→C，长度6
B先走1步到6，此时A在4
同步：(4,6)→(1,1)；这里两个1只是值相同，引用不同
再走：(8,8)，指向共享的8，返回这个节点
```

#### Java主解

```java
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        int lenA = getLength(headA);
        int lenB = getLength(headB);
        ListNode curA = headA;
        ListNode curB = headB;
        while (lenA > lenB) {
            curA = curA.next;
            lenA--;
        }
        while (lenB > lenA) {
            curB = curB.next;
            lenB--;
        }
        while (curA != curB) {
            curA = curA.next;
            curB = curB.next;
        }
        return curA;
    }

    private int getLength(ListNode head) {
        int length = 0;
        while (head != null) {
            length++;
            head = head.next;
        }
        return length;
    }
}
```

#### 易错点与复杂度

测试必须真的共享尾部对象，分别new出相同数字不算相交。返回节点引用，不能新建同值节点。空链表或无交点都返回null。

时间O(m+n)，额外空间O(1)。

#### 扩展解法与方法对比

##### 双链表拼接：到null后换到另一条头

保留原文第二解法，对应代码随想录双指针拼接思路。用走另一条链的前缀自动补齐差值。

1. a从A出发，到null的下一轮换到headB；b对称地从B换到headA。每次循环都各做一次移动或换头。
2. 设A独有长度a、B独有长度b、共享长度c；换头后抵达交点时，两边都经过a+b+c个真实节点的路径，并各经历一次null换头。
3. 若不相交，二者最终同时为null。相交时通常提前结束，不必真的各走完整的A+B。

同一输入以“A/B各节点位置”记录：初始(4A,5B)→(1A,6B)→(8,1B)→(4C,8)→(5C,4C)→(null,5C)→(5B,null)→(6B,4A)→(1B,1A)→(8,8)，返回共享8。

```java
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        ListNode a = headA;
        ListNode b = headB;
        while (a != b) {
            if (a == null) {
                a = headB;
            } else {
                a = a.next;
            }
            if (b == null) {
                b = headA;
            } else {
                b = b.next;
            }
        }
        return a;
    }
}
```

时间O(m+n)，额外空间O(1)，不需要先统计长度。

| 双链表拼接：到null后换到另一条头 | 保留原文第二解法，对应代码随想录双指针拼接思路。用走另一条链的前缀自动补齐差值。 | 时间O(m+n)，额外空间O(1)，不需要先统计长度。 |

## 8. 快慢指针与环

### [141. 环形链表【前置补充题】](https://leetcode.cn/problems/linked-list-cycle/)

[交互式调试器 · 141. 环形链表](https://xiaoshupeiqi.github.io/leetcode-java/problems/0141-linked-list-cycle/)

#### 一句话总结

> 这道题本质是：在环里快指针不断缩小相对距离；能到null则无环。

#### 拿到题目怎么想

1. 顺着next走，若重复访问同一个对象就有环。用集合可做，但要额外记录节点。
2. 想省空间，用slow每次一步、fast每次两步。无环时fast先到null；有环时都进入环后，每轮相对前进一格，最终追上。
3. 两者初始都在head，不能把初始相等算成有环。先移动，再比较slow==fast。
4. 快指针要读fast.next.next，循环先保证fast与fast.next都非null；无环退出后返回false。

#### 关键变量与循环不变量

slow、fast保存节点引用；是否相遇比较对象身份。相遇可能在环内任何节点，不一定是入口。

#### 实例走过程

```text
head=[3,2,0,-4], pos=1（尾部-4.next指回节点2）
初始slow=3、fast=3，不判相遇
第1轮slow=2，fast=0
第2轮slow=0，fast=2
第3轮slow=-4，fast=-4 → true
pos仅用于构造测试，不是hasCycle的参数
```

#### Java主解

```java
public class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                return true;
            }
        }
        return false;
    }
}
```

#### 易错点与复杂度

不同节点的val可以相同，不能比较值。空链表、单节点无环返回false；单节点指向自己返回true。不要修改next做访问标记。

时间O(n)，额外空间O(1)；n为可到达的不同节点数。

#### 扩展解法与方法对比

##### 集合：记录走过的节点引用

学习扩展，直接实现第一思路，用额外空间换直观性。

1. 逐节点加入Set<ListNode>；默认力扣ListNode没有重写equals/hashCode，集合比较的是对象身份。
2. add返回false表示该对象曾经访问过，即有环；走到null则无环。
3. 主解不存访问历史，只保持两个引用，额外空间更小。

同一输入按3、2、0、-4依次加入，再访问原来的2时加入失败，返回true。

```java
import java.util.*;

public class Solution {
    public boolean hasCycle(ListNode head) {
        Set<ListNode> seen = new HashSet<>();
        ListNode cur = head;
        while (cur != null) {
            if (!seen.add(cur)) {
                return true;
            }
            cur = cur.next;
        }
        return false;
    }
}
```

时间O(n)（集合操作按平均O(1)），额外空间O(n)。

### [142. 环形链表 II](https://leetcode.cn/problems/linked-list-cycle-ii/)

[交互式调试器 · 142. 环形链表 II](https://xiaoshupeiqi.github.io/leetcode-java/problems/0142-linked-list-cycle-ii/)

#### 一句话总结

> 这道题本质是：第一次相遇确认有环；从head和相遇点同速走，第二次相遇才是入口。

#### 拿到题目怎么想

1. 先复用141的快慢指针检测；如果fast到null，直接返回null。仅检测出相遇点还不足以回答入口。
2. 相遇后，一个指针从head走，另一个从相遇点走，每次都一步；它们第一次重合的位置就是入口。
3. 理解关键关系即可：设入口前长x，环周长c，相遇点距入口y，则相遇时慢指针路程x+y是c的整数倍，所以从相遇点再走x步恰好到入口。
4. 第二阶段先检查index1!=index2再移动，兼容head本来就是入口的情况。返回原节点引用，不改next。

#### 关键变量与循环不变量

第一阶段slow每轮一步、fast两步；第二阶段index1=head、index2=相遇点，两者每轮同走一步。

#### 实例走过程

```text
同141输入：[3,2,0,-4], pos=1
检测第3轮：slow与fast在-4相遇
index1从3、index2从-4出发；各走一步都到同一个节点2
返回节点2（入口），不是相遇点-4
若整个链表就是一个环，可能在head相遇；第二阶段可以0步结束
```

#### Java主解

```java
public class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                ListNode index1 = head;
                ListNode index2 = slow;
                while (index1 != index2) {
                    index1 = index1.next;
                    index2 = index2.next;
                }
                return index1;
            }
        }
        return null;
    }
}
```

#### 易错点与复杂度

不要直接返回第一次相遇点。第二阶段两个指针都走一步；pos不是函数参数。返回入口对象，值相等不代表找对入口。

时间O(n)，额外空间O(1)。

#### 扩展解法与方法对比

##### 集合：第一次重复访问的节点就是入口

学习扩展，与141集合版只有返回值不同。

1. 从head沿next顺序访问并记录对象；前缀不重复，首次重复只能发生在进入环的第一个节点。
2. add失败时返回cur；走到null则无环，返回null。
3. 与141的区别是返回重复的节点引用，而非true。

同一输入访问3→2→0→-4→2；第二次遇到的2就是入口，返回该对象。

```java
import java.util.*;

public class Solution {
    public ListNode detectCycle(ListNode head) {
        Set<ListNode> seen = new HashSet<>();
        ListNode cur = head;
        while (cur != null) {
            if (!seen.add(cur)) {
                return cur;
            }
            cur = cur.next;
        }
        return null;
    }
}
```

时间O(n)（集合操作按平均O(1)），额外空间O(n)。

| 写法 | 选择依据 | 代价 |
| --- | --- | --- |
| 主解（调试器对应） | 第一阶段slow每轮一步、fast两步；第二阶段index1=head、index2=相遇点，两者每轮同走一步。 | 时间O(n)，额外空间O(1)。 |
| 集合：第一次重复访问的节点就是入口 | 学习扩展，与141集合版只有返回值不同。 | 时间O(n)（集合操作按平均O(1)），额外空间O(n)。 |

## 复习时最容易错的地方

### 1. 修改 `next` 前没保存后继

错误风险：

```Java
cur.next = prev;
cur = cur.next;
```

此时 `cur.next` 已经被你改过，原链表后面部分可能直接丢失。

正确思路：

```Java
ListNode next = cur.next;
cur.next = prev;
cur = next;
```

---

### 2. 删除节点后无条件移动 cur

连续删除时可能漏节点。

应该：

```Java
if (cur.next.val == val) {
    cur.next = cur.next.next;
} else {
    cur = cur.next;
}
```

---

### 3. 相交链表比较了 val

错误：

```Java
curA.val == curB.val
```

正确：

```Java
curA == curB
```

链表相交要求的是**同一个节点对象**。

---

### 4. 快指针空指针

错误风险：

```Java
fast = fast.next.next;
```

必须保证：

```Java
while (fast != null && fast.next != null)
```

---

### 5. 忘记 dummy 最终不能直接返回

虚拟头结点不是原链表节点。

最终通常返回：

```Java
return dummy.next;
```
